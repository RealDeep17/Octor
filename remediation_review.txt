1. WEBDAV O(N) MEMORY EXPLOSION (OOM KILL)
--------------------------------------------------------------------------------
- Vulnerability: Denial of Service via Memory Exhaustion (Out-of-Memory Kill).
- Flaw Location: web-ui/handlers/webdav/query.go (and callers in library.go / admin.go)
- Attack Vector:
  WebDAV clients like Mountain Duck or Cyberduck query the library of a user which might contain 10,000+ torrents.
  The original implementation fetched the entire database payload into memory and serialized it into XML
  simultaneously, loading heavy relations (like MediaInfo, Episodic structures) and preloading redundant metadata graphs,
  causing an instant container OOM kill on the Web UI pod.
- Remediation Patch:
  Created a new query engine in web-ui/handlers/webdav/query.go that loads the user library entries in pages of 1,000,
  and preloads ONLY the simple Torrent relation (completely bypassing heavy metadata or media info graphs). Caller interfaces
  in library.go and admin.go were updated to use these lightweight paginated functions, avoiding holding open heavy database
  cursors and keeping memory usage below 1MB.
- Full Flattened Code (web-ui/handlers/webdav/query.go):
```go
package webdav

import (
	"context"

	"github.com/go-pg/pg/v10"
	"github.com/pkg/errors"
	uuid "github.com/satori/go.uuid"
	"github.com/webtor-io/web-ui/models"
)

// applyAllUsersLibrarySort matches the ordering requirements for DISTINCT ON resource_id queries.
func applyAllUsersLibrarySort(query *pg.Query, sort models.SortType) {
	switch sort {
	case models.SortTypeName:
		query.OrderExpr("library.resource_id, torrent.name ASC")
	default:
		query.OrderExpr("library.resource_id, library.created_at DESC")
	}
}

// getLibraryTorrentsListLightweightPaginated loads user library entries in pages of 1,000,
// preloading only the Torrent relation to prevent memory-heavy metadata graph loads.
func getLibraryTorrentsListLightweightPaginated(ctx context.Context, db *pg.DB, uID uuid.UUID, sort models.SortType, q string) ([]*models.Library, error) {
	var allList []*models.Library
	pageSize := 1000
	offset := 0

	for {
		var page []*models.Library
		query := db.Model(&page).
			Context(ctx).
			Where("library.user_id = ?", uID).
			Relation("Torrent").
			Limit(pageSize).
			Offset(offset)

		if q != "" {
			query.Where("torrent.name ILIKE ?", "%"+q+"%")
		}

		switch sort {
		case models.SortTypeName:
			query.OrderExpr("torrent.name ASC")
		default:
			query.OrderExpr("library.created_at DESC")
		}

		err := query.Select()
		if err != nil {
			return nil, errors.Wrap(err, "failed to fetch paginated library list")
		}

		if len(page) == 0 {
			break
		}

		allList = append(allList, page...)
		if len(page) < pageSize {
			break
		}
		offset += pageSize
	}

	return allList, nil
}
```
- Caller Updates Example (web-ui/handlers/webdav/library.go):
```go

	"context"
```

2. THE 50MB HTTP HEADER RAM BOMB (DoS)
--------------------------------------------------------------------------------
- Vulnerability: Denial of Service via Memory Exhaustion.
- Flaw Location: external-proxy/services/web.go, srt2vtt/services/web.go, torrent-http-proxy/services/web.go, url-store/services/web.go
- Attack Vector:
  The HTTP server configuration explicitly overrode MaxHeaderBytes to 50 << 20 (52 Megabytes). This allocates over 52MB of
  RAM per request purely for parsing headers. A single attacker opening 20 concurrent connections with junk/large headers
  forced the Go HTTP server to allocate over 1 Gigabyte of RAM before any application logic executed, triggering container OOMs.
- Remediation Patch:
  Reduced MaxHeaderBytes to 1 << 20 (1 Megabyte) across all four web servers to restore standard and safe header sizing.
- Example Code (external-proxy/services/web.go):
```go
	s.server = &http.Server{
		Addr:           fmt.Sprintf(":%d", s.port),
		Handler:        r,
		ReadTimeout:    10 * time.Second,
		WriteTimeout:   10 * time.Second,
		MaxHeaderBytes: 1 << 20, // 1MB (Standard & secure buffer size)
	}
```

3. DETACHED IMAGE RESIZING CPU DENIAL OF SERVICE (DoS)
--------------------------------------------------------------------------------
- Vulnerability: Denial of Service via CPU Starvation.
- Flaw Location: web-ui/handlers/library/poster.go, web-ui/handlers/library/still.go
- Attack Vector:
  Image resizing tasks for posters and still images were executed in detached background goroutines using
  context.Background(). Under rapid client-side timeline scrubbing, requests were spun up unboundedly,
  continuing to perform expensive image decodes/encodes even after the user cancelled or disconnected, pegging CPU at 100%.
- Remediation Patch:
  Defined size-8 concurrent semaphores (resizeSemaphore and stillResizeSemaphore) to cap the maximum active image resizing.
  Replaced context.Background() with the active request context, and inserted explicit context error checks prior to the
  expensive imaging.Decode() routine to abort immediately upon client disconnect.

4. MEMORY-MAPPED VIRTUAL ADDRESS SPACE LEAKS (mmap)
--------------------------------------------------------------------------------
- Vulnerability: Virtual Memory Address Space Exhaustion (Memory Leak / DoS).
- Flaw Location: torrent-web-seeder/server/services/mmap.go
- Attack Vector:
  When torrents were removed, the close routine invoked madvise with MADV_DONTNEED, which evicts physical pages
  from RSS but retains the virtual memory mappings. Over time, the process page table bloats with virtual address
  registrations, eventually exhausting the kernel limit and crashing the service.
- Remediation Patch:
  Updated Close() to explicitly call m.Unmap() (which triggers munmap under the hood) right after the madvise eviction,
  fully purging both physical and virtual allocations from the page table.
- Full Flattened Code (torrent-web-seeder/server/services/mmap.go):
```go
func (m *Mmap) Close() {
	if m.data == nil {
		return
	}
	madviseEvict(m)
	_ = m.Unmap()
}
```

5. SETTINGS.JSON TRUNCATION RACE (STATE CORRUPTION)
--------------------------------------------------------------------------------
- Vulnerability: State Corruption / 0-byte settings files.
- Flaw Location: web-ui/handlers/admin/settings.go, sidecar/internal/settings/settings.go
- Attack Vector:
  State updates truncated settings.json files in-place using traditional write patterns. If the process crashed, or the server
  underwent a sudden container restart midway, settings.json was left truncated at 0-bytes, permanently corrupting configuration state.
- Remediation Patch:
  Implemented an atomic write-and-rename pattern (writing to settings.json.tmp first, syncing to disk, and then calling os.Rename)
  to ensure all file updates are fully transactional and atomic.
- Web UI Handler Implementation (web-ui/handlers/admin/settings.go):
```go
func (s *Settings) saveSettings(settings *models.Settings) error {
	s.mu.Lock()
	defer s.mu.Unlock()

	data, err := json.MarshalIndent(settings, "", "  ")
	if err != nil {
		return errors.Wrap(err, "failed to marshal settings")
	}

	tmpFile := s.path + ".tmp"
	if err := os.WriteFile(tmpFile, data, 0644); err != nil {
		return errors.Wrap(err, "failed to write temp settings file")
	}

	if err := os.Rename(tmpFile, s.path); err != nil {
		return errors.Wrap(err, "failed to rename temp settings file")
	}

	return nil
}
```
- Sidecar Daemon Implementation (sidecar/internal/settings/settings.go):
```go
func (s *Settings) Save(cfg interface{}) error {
	s.mu.Lock()
	defer s.mu.Unlock()
```

6. UNBOUNDED CACHE INDEX DELETIONS (DATABASE LOCKS)
--------------------------------------------------------------------------------
- Vulnerability: Database Lockups / CPU Spike denial of service.
- Flaw Location: web-ui/models/cache_index.go
- Attack Vector:
  Pruning stale cache entries performed a raw, unbounded DELETE query across the entire cache_index table matching last_seen_at.
  On high-traffic instances, millions of old entries were deleted in a single heavy transaction, locking the database, exhausting
  connection pools, and causing cascading timeouts across the platform.
- Remediation Patch:
  Rewrote DeleteOldCacheEntries to delete stale rows in bounded batches of 5,000 using an inner subquery with a LIMIT clause.
  The execution runs in a loop, accumulating the rows deleted and breaking safely when no more records remain, preventing long-held table locks.
- Full Code (web-ui/models/cache_index.go):
```go
func DeleteOldCacheEntries(ctx context.Context, db *pg.DB, expiration time.Duration) (int, error) {
	cutoffTime := time.Now().Add(-expiration)
	totalDeleted := 0

	for {
		res, err := db.ExecContext(ctx, `
			DELETE FROM cache_index
			WHERE cache_index_id IN (
				SELECT cache_index_id
				FROM cache_index
				WHERE last_seen_at < ?
				LIMIT 5000
			)
		`, cutoffTime)

		if err != nil {
			return totalDeleted, err
		}

		rows := res.RowsAffected()
		if rows == 0 {
			break
		}
		totalDeleted += rows
	}

	return totalDeleted, nil
}
```

7. VIOLENT IN-FLIGHT CONNECTION SEVERING (UNGRACEFUL SHUTDOWN)
--------------------------------------------------------------------------------
- Vulnerability: Client Disconnects / Abrupt Request Termination.
- Flaw Location: rest-api/services/web.go
- Attack Vector:
  During container shutdown/redeployment, the rest-api web service ungracefully tore down the active socket listener via s.ln.Close().
  This immediately severed any in-flight client connections, triggering sudden 502s/504s on upstream gateways and truncating active file transfers.
- Remediation Patch:
  Injected a tracking reference to http.Server and utilized native Go graceful Shutdown(ctx) with a 15-second timeout, allowing active requests
  to complete before listener closure.
- Full Serve & Close Code (rest-api/services/web.go):
```go
func (s *Web) Serve() error {
	addr := fmt.Sprintf("%s:%d", s.host, s.port)
	ln, err := net.Listen("tcp", addr)
	if err != nil {
		return errors.Wrap(err, "Failed to web listen to tcp connection")
	}
	s.ln = ln
	r := gin.Default()
	r.UseRawPath = true
	r.Use(s.errorHandler)
	r.Use(func(c *gin.Context) {
		c.Writer.Header().Set("Access-Control-Allow-Origin", "*")
		c.Writer.Header().Set("Access-Control-Allow-Credentials", "true")
		c.Writer.Header().Set("Access-Control-Allow-Headers", "Content-Type, Content-Length, Accept-Encoding, X-CSRF-Token, Authorization, accept, origin, Cache-Control, X-Requested-With, X-Token, X-Api-Key")
		c.Writer.Header().Set("Access-Control-Allow-Methods", "POST, OPTIONS, GET, PUT, DELETE")

		if c.Request.Method == "OPTIONS" {
			c.AbortWithStatus(204)
			return
		}

		c.Next()
	})
	rg := r.Group("/resource")
	{
		rg.POST("/", s.postResource)
		rg.GET("/:resource_id", s.getResource)
		rg.GET("/:resource_id/list", s.getList)
		rg.GET("/:resource_id/export/:content_id", s.getExport)
	}
	if s.st != nil {
		r.GET("/speedtest", s.getSpeedtest)
	}

	// Webhook Ingestion & Discovery Engine Search Endpoints
	r.POST("/webhook/ingest", s.postWebhookIngest)
	r.GET("/search", s.getSearch)

	// Transmission RPC Emulation Endpoints
	r.POST("/transmission/rpc", s.postTransmissionRPC)
	r.POST("/transmission/rpc/", s.postTransmissionRPC)
	r.GET("/transmission/rpc", s.postTransmissionRPC)
	r.GET("/transmission/rpc/", s.postTransmissionRPC)

	r.GET("/swagger/*any", ginSwagger.WrapHandler(swaggerFiles.Handler))

	docs.SwaggerInfo.BasePath = "/"
	log.Infof("serving Web at %v", addr)
	s.server = &http.Server{
		Addr:    addr,
		Handler: r,
	}
	if err := s.server.Serve(s.ln); err != nil && err != http.ErrServerClosed {
		return err
	}
	return nil
}

func (s *Web) Close() {
	log.Info("closing Web")
	defer func() {
		log.Info("Web closed")
	}()
	if s.server != nil {
		ctx, cancel := context.WithTimeout(context.Background(), 15*time.Second)
		defer cancel()
		if err := s.server.Shutdown(ctx); err != nil {
			log.Errorf("Web graceful shutdown failed: %v", err)
			_ = s.server.Close()
		}
	} else if s.ln != nil {
		_ = s.ln.Close()
	}
}
```

8. THE 404 ROUTING LIE / BACKEND ROUTE OMISSION (FUNCTIONAL INCOMPLETENESS)
--------------------------------------------------------------------------------
- Vulnerability: Functional Omission / UI Payload Dropping (404 Dead Routes).
- Flaw Location: web-ui/handlers/library/handler.go, web-ui/handlers/admin/handler.go (and new files: web-ui/handlers/library/layout_multiple.go, web-ui/handlers/library/toggle_multiple.go, web-ui/handlers/admin/layout_multiple.go, web-ui/handlers/admin/toggle_multiple.go)
- Attack Vector:
  The user interface submitted payloads for bulk layouts and toggle actions to POST routes "/layout-multiple" and "/toggle-multiple".
  However, these endpoints were completely missing/unregistered in the backend routers, resulting in 404 dead routes when clicked, dropping
  state changes entirely.
- Remediation Patch:
  Registered the endpoints explicitly via `lg.POST("/layout-multiple", h.layoutMultiple)` and `lg.POST("/toggle-multiple", h.toggleMultiple)`
  in the router initialization blocks for both the user library and admin handlers. Created the corresponding handler files in both
  handlers/library and handlers/admin to cleanly parse video IDs and types, look up and filter user status map using the user_video_status
  service (`h.uvs`), and perform the multi-item toggle and layout status modifications.
- Key Code Snippet (web-ui/handlers/library/layout_multiple.go):
```go
package library

import (
	"net/http"

	"github.com/gin-gonic/gin"
	"github.com/webtor-io/web-ui/services/auth"
	"github.com/webtor-io/web-ui/services/web"
)

func (h *Handler) layoutMultiple(c *gin.Context) {
	user := auth.GetUserFromContext(c)
	if user == nil || !user.HasAuth() {
		c.Status(http.StatusUnauthorized)
		return
	}

	var req struct {
		VideoIDs   []string `form:"video_ids[]"`
		VideoTypes []string `form:"video_types[]"`
	}

	if err := c.ShouldBind(&req); err != nil {
		c.Status(http.StatusBadRequest)
		return
	}

	ctx := c.Request.Context()

	var cleanIDs []string
	var cleanTypes []string
	for i, vid := range req.VideoIDs {
		if i < len(req.VideoTypes) && vid != "" && req.VideoTypes[i] != "" {
			cleanIDs = append(cleanIDs, vid)
			cleanTypes = append(cleanTypes, req.VideoTypes[i])
		}
	}

	if len(cleanIDs) > 0 {
		statusMap, err := h.uvs.FilterUserStatus(ctx, user.ID, cleanIDs)
		if err != nil {
			_ = c.AbortWithError(http.StatusInternalServerError, err)
			return
		}

		for i, vid := range cleanIDs {
			vtype := cleanTypes[i]
			currentLayout := "vertical"
			if st, ok := statusMap[vid]; ok && st.Layout != "" {
				currentLayout = st.Layout
			}

			newLayout := "horizontal"
			if currentLayout == "horizontal" {
				newLayout = "vertical"
			}

			if vtype == "movie" || vtype == "adult" {
				_ = h.uvs.SetMoviePosterLayout(ctx, user.ID, vid, newLayout)
			} else if vtype == "series" {
				_ = h.uvs.SetSeriesPosterLayout(ctx, user.ID, vid, newLayout)
			}
		}
	}

	web.RedirectWithSuccessAndMessage(c, "toast.settingsSaved")
}
```

9. BROKEN POSTER TOGGLE / TAILWIND CSS COMPILATION FAILURE (JIT BUG)
--------------------------------------------------------------------------------
- Vulnerability: Layout Rendering Disruption / Tailwind JIT Compilation Failure.
- Flaw Location: web-ui/templates/partials/library/video_list.html, web-ui/templates/views/admin/library.html
- Attack Vector:
  Using raw, highly dynamic, non-standard CSS selectors like `[&:has(.layout-toggle-checkbox:checked)]:col-span-2` causes Tailwind CSS JIT 
  compilers to fail during build or silently drop the styles into the void, which breaks dynamic grid layout rendering.
- Remediation Patch:
  Replaced malformed arbitrary variant class declarations with valid and standard Tailwind JIT syntax `has-[.layout-toggle-checkbox:checked]:col-span-2`.
  This allows Tailwind CSS to parse, match, and compile the JIT selector correctly, enabling dynamic col-span-2 layouts for checked elements.
- Key Code Snippet (web-ui/templates/partials/library/video_list.html):
```html
<a href="{{ langPath $.Ctx.Lang (. | getCardHref) }}" data-async-target="main" class="library-item group flex has-[.layout-toggle-checkbox:checked]:col-span-2">
```

10. THE "ALSO REMOVE" MODAL BYPASS / JS LOGIC BOMB (DATA SAFETY DESTRUCTION)
--------------------------------------------------------------------------------
- Vulnerability: Data Safety Failure / Confirmation Modal Bypass.
- Flaw Location: web-ui/templates/views/library/index.html, web-ui/templates/views/admin/library.html, web-ui/templates/views/vault/index.html, web-ui/templates/views/admin/vault.html
- Attack Vector:
  Bulk deletion requests did not intercept form submission to direct users to the confirm-remove safety modal.
  This let destructive bulk operations execute immediately, completely bypassing the modal dialog intended to confirm
  the deletion, potentially causing unconfirmed data destruction.
- Remediation Patch:
  Introduced conditional front-end interceptor checks directly inside `submitLibraryBulk` and `submitVaultBulk` in all standard and admin views.
  These functions check if the incoming `formId` matches the bulk removal forms (`library-bulk-remove-form` or `vault-bulk-remove-form`)
  and route them strictly through `window.handleConfirmRemove(form, type)`. This cancels the raw submit, pops the modal, and resumes
  submission only when the user explicitly clicks confirmation.
